# Background mode

`prosetta:cycle` keeps every language current without anyone running commands. Each cycle syncs your lang files, confirms edits that don't need the AI, drafts what's new or changed, then approves and exports according to your settings.

Run it where your lang files live and get committed: a development machine (next to `composer dev`) or CI. Not production: production can't commit lang files. (To approve on the live site, see [Reviewing in production](production-review.md).)

## Turning it on

```php
// config/prosetta.php
'automation' => [
    'every' => 10,          // minutes between cycles; null = no schedule
    'approve' => 'all',     // 'all', 'none' (stop at drafts), or a list of language codes
    'export' => true,       // write lang files after approving
    'rewrite_ratio' => 3.0, // flag an update that rewrote much more than the English changed
],
```

With `every` set, Prosetta schedules `prosetta:cycle` itself. Laravel's scheduler must be running (`php artisan schedule:work` locally, or a cron entry calling `schedule:run` every minute), along with a queue worker for the `prosetta.queue.name` queue (`translations` by default).

You can also run a cycle by hand: `php artisan prosetta:cycle`.

## What one cycle does

1. **Checks the last cycle has finished.** If it's still running, this one exits quietly. A cycle that died mid-run is only treated as abandoned after `max(60 minutes, 2 × every)`.
2. **Syncs** every namespace.
3. **Confirms cosmetic edits** without the AI (see [below](#cosmetic-edits)).
4. **Works out what needs drafting:** strings whose English changed substantively, in every language that had an approved translation, and new or missing strings in languages set to `auto_translate`.
5. **Queues the drafts** as one run, so [budgets and circuits](resilience.md) apply.
6. **Finishes** once the drafts are done:
   - approves **this cycle's own** AI drafts that have no issues at all (not even a warning), per `automation.approve`;
   - exports the languages that got an approval, when `automation.export` is true;
   - records the time, and raises the `CycleCompleted` event with a report.

A cycle with nothing to do still records its time and raises `CycleCompleted`, so you can tell it's alive.

**The cycle never approves someone else's work.** It only approves AI drafts it made itself, still in draft, with no issues. It never touches a draft from an earlier run or a person's pending edit.

### What the export leaves alone

When the cycle exports, it won't overwrite:

- **a lang file with a person's edit waiting for review.** It's reported as `"{locale} {path} (export held: …)"` so the edit isn't reverted;
- **a PHP lang file Prosetta didn't generate** (no "Generated by Prosetta" header), such as a hand-written file. It's reported as held.

When you first adopt Prosetta, run `prosetta:export` once by hand to take over your existing files; the cycle writes them from then on. (JSON files have no header, so this check covers PHP files only.)

### What the cycle holds back

Two kinds of string are left out of the drafting and reported as flagged, with a reason:

- **A person's own translation waiting for review** is never sent to the AI: `"{locale} {ref} (awaiting human review)"`.
- **A string that keeps failing.** Each time the provider refuses a string or returns nothing for it, Prosetta counts it. After 3 failures from the same English, the cycle stops sending it and reports it as skipped. Editing the English resets the count, and a successful draft clears it.

## In CI

```bash
php artisan prosetta:cycle --sync
```

`--sync` runs the whole cycle inline and exits 1 when anything is flagged, when an approved translation is still based on older English, or when a run was paused. It prints each flagged string. Use it as a gate, so review happens in the lang files' git diff.

## Language settings

Four columns on `prosetta_locales` shape how each language is drafted:

| Column | Type | Does |
|---|---|---|
| `auto_translate` | boolean | The cycle drafts **every** string this language is missing, not just ones whose English changed. |
| `style_note` | text | Sent with every batch for this language, e.g. "Informal, second person singular." |
| `glossary` | json | Terms to translate a fixed way (see [below](#glossaries)). |
| `replacements` | json | Makes the language a spelling variant of the source (see [below](#spelling-variants-like-en_gb)). |

A regional code without its own `style_note` or `glossary` borrows its base language's, field by field: `es_MX` with no `style_note` uses `es`'s.

## Glossaries

A glossary keeps key terms consistent. Each entry names the English term and the translation to use:

```json
[
    {"source": "cohort", "target": "دفعة", "accept": ["دفعت", "دفعات"], "banned": ["فوج", "مجموعة"]}
]
```

For every entry whose `source` appears in the English (as a whole word, singular or plural, any case):

- **The translation should contain `target`**, or one of the forms in `accept`. If it contains none, the draft gets a `glossary_missing` warning. The check is a plain substring match, because many scripts don't separate words with spaces. Use `accept` for forms a substring can't catch: Arabic `دفعة` becomes `دفعات` in the plural and `دفعتك` with a suffix.
- **The translation must not contain a `banned` term.** If it does, that's a `glossary_banned` error, and the draft gets its retry with the correction explained.

Warnings stop a draft being approved automatically, but don't stop it being exported with `--include-drafts`.

## Spelling variants like en_GB

A variant that differs from the source only in spelling (British `en_GB` from American `en`) doesn't need the AI. Give it `replacements`:

```json
[
    {"from": "color", "to": "colour"},
    {"from": "colors", "to": "colours"},
    {"from": "organize", "to": "organise"}
]
```

Every string is then made from the English by swapping whole words. Capitalisation is kept (Color → Colour), and placeholders (`:color`), HTML tags and URLs are left alone. List each form you need, since only whole words match. Leave out words whose spelling depends on meaning (program/programme, practice/practise) and fix those strings by hand.

Variant strings cost no tokens and never reach your driver. They're approved and exported by the cycle like AI drafts, so an English edit reaches the variant on the next cycle. Their lang files hold only the strings the swaps change; Laravel falls back to the source language for the rest. Turn on `auto_translate` too, so new strings are made as well as changed ones.

To convert an existing language to a variant once:

```bash
php artisan prosetta:translate --locale=en_GB --force --sync
php artisan prosetta:review en_GB --approve-clean
php artisan prosetta:export --locale=en_GB
```

## When the English changes

### Cosmetic edits

When you tweak English without changing its meaning (fixing capitalisation, curly quotes, spacing or a trailing full stop), the translations don't need redoing. Before drafting anything, each cycle compares every approved translation's original English with the new English, ignoring case, quote and dash styles, extra spaces and trailing punctuation. If they match, the translation is **confirmed**: re-approved against the new English, with no AI call.

### Substantive edits

Anything else goes to the AI as an **update**. The driver receives the old English as `previousSource` next to the new one, and can show the model a word-level diff with `SourceChange::diff()`.

If the new translation changed much more than the English did (by more than `automation.rewrite_ratio`, and by more than two words), it gets a `large_rewrite` warning and isn't approved automatically.

**Which languages get updates:** every language with an approved translation of the edited string. **Which get drafts of strings they never had:** only languages with `auto_translate` on.

## Keeping an eye on it

```bash
php artisan prosetta:health
```

Exits 0 and prints `healthy`, or exits 1 and prints one line per problem:

| Code | Means |
|---|---|
| `[cycle_stale]` | The last cycle is older than `3 × automation.every` |
| `[circuit_halted:{name}]` | A provider has halted (see [resilience](resilience.md)) |
| `[budget:{period}]` | A daily or monthly token budget is spent |

The text after each code can change between runs (it includes the cycle's age), so an alerting system should de-duplicate by the codes.

### Events

`CycleCompleted` carries a `CycleReport` with `drafted`, `updated`, `confirmed`, `approved`, `flagged` (each flagged item with its reason), `files` (paths written) and `tokens`. Prosetta sends no mail itself: listen for the event and notify people your way. The [resilience events](resilience.md#events) tell you when drafting stopped.
